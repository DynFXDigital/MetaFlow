# MetaFlow 0.4.7

This point release improves standards-backed plugin authoring, protects strict Agent Plugins v1 packages during metadata maintenance, and makes repository identity clearer.

## Highlights

- Built-in **Agent Plugins** and **Agent Skills** capabilities provide concise authoring guidance with pinned specification, schema, and license references.
- Authoring guidance distinguishes GitHub Copilot plugins from strict Agent Plugins v1 packages and asks for the intended format when a request is ambiguous.
- Existing metadata-authoring guidance links to the shared standards capabilities.

## Fixes

- Recognize strict Agent Plugins v1 manifests and report compatibility diagnostics without treating host-specific plugin layouts as portable v1 packages.
- Preserve recognized v1 packages during metadata maintenance; reject fatal manifest errors, unsupported schema versions, and mixed host-specific fields without rewriting packages as Copilot plugins. Inspection follows the standard's non-fatal diagnostic rules for unknown fields and unsupported components.
- Keep stable plugin names separate from human-readable display names, including when maintaining plugin metadata.
- Honor configured repository names and prefer stable repository identifiers over incidental local folder names.
- Derive new repository identifiers and display names from Git URLs or selected directories while preserving legacy migration identities.

## Scope

Authoring support is supplied through bundled agent guidance; this release does not add a strict-v1 package-scaffolding command. Pi target projection, Pi lifecycle configuration, and automatic Git remote promotion are not included.
